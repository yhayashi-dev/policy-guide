# 編集・更新手順

1. 対象となる制度・法案を特定する。法律名、会期、議案番号、法律番号を確認し、似た法案を混ぜない。
2. 国会の議案審議情報で提出・議決・成立・公布を確認する。政策議論と法案提出を区別する。
3. 省庁・実施機関の最新案内で開始日・対象・経過措置を確認する。古いページだけで最新と判断しない。
4. 数字や期日が異なる場合、資料の更新時点・対象年度・条件の差を記録する。裏付けられない事実は掲載しない。
5. 意見は議事録等で発言者と文脈を確認する。制度全体への反対、部分的な懸念、実施条件への要望を区別する。過去の意見を今の賛否とは表示しない。
6. content/sources.jsonに資料ID・正式タイトル・発行元・URL・checkedAt・確認箇所を記録する。IDは既存と重複させず、安定した値を使う。
7. content/articles.jsonの本文とrefsを更新。status/enacted/pendingは人が確認して設定。eventsのplannedを日付だけで変更しない。法律が廃案となった場合も別の再提出法案へ履歴を流用しない。
8. checkedAtは実際に照合した日、updatedAtは記事を修正した日、publishedAtは初回掲載日。reviewAfterは次回確認目安。トップの確認日は記事データから集計する。
9. CHANGELOGに変更理由と出典を記録。法的効果に関わる訂正は、該当記事のreviewNoteにも明示する。
10. pnpm test / pnpm typecheck / pnpm lint / pnpm build / pnpm check:links。必要に応じて外部リンク確認。更新した記事をスマートフォンとPCで読む。
11. 公開前に対象URLと公開範囲を確認し、GitHub Actionsを手動実行。

## 更新頻度の目安
- 審議中：週1回と議決・廃案等の後
- 施行待ち：月1回と開始日の前後
- 施行済み：公式更新時。古くなった記事は再確認まで日付を維持
- 定期的に node scripts/review-due.mjs で確認期限を一覧化

外部URLの取得は任意のチェックコマンドのみ。自動収集、定期ジョブ、メール通知は設定していない。将来の自動監視はURL差分を確認対象として示す範囲に留め、法案状態と本文の変更は人が判断する。

## 公開時に整備するもの
運営者名、訂正窓口、公開URLを設定する。実在しない連絡先は記載しない。解析・広告・外部フォームを追加する場合は、必要に応じてプライバシー方針を追加する。

## 30テーマ版の更新

継続審査の8記事は国会の議案経過を週単位で再確認します。施行待ちの記事は政令・所管省庁の施行案内を確認し、日付の確定と実際の施行を分けて更新します。反対・慎重側の一次資料が未確認の項目は継続調査し、発言者・日付・文脈を確認して追記します。確認日だけを自動で進めません。
